# リール動画エディター

動画素材1本から、無音カット・日本語字幕・BGM付きの縦型 MP4 を自動作成する最小構成です。Python と FFmpeg を使い、ブラウザの簡単な操作画面から実行できます。

## 費用と外部通信

有料 API や外部文字起こしサービスは使いません。音声認識は faster-whisper / Whisper を使って PC の CPU 上で実行します。初回は Hugging Face から無料のモデルをダウンロードし、以降はキャッシュを利用します（通信量・ストレージ・電気代は利用者負担）。動画・音声を文字起こしサービスへ送信しません。Python パッケージのインストールにもインターネット接続が必要です。モデルは `tiny`、`base`、`small`、`medium` の順におおむね高精度・低速・大容量になります。まずは `base` をお試しください。メモリ 8GB 以上を推奨します。

## セットアップ

Python 3.10〜3.12、FFmpeg（ffprobe・libx264・libass を含む）、日本語フォントが必要です。

1. Python をインストールしてください。Windows ではインストーラーの「Add Python to PATH」を有効にします。
2. FFmpeg をインストールし、ターミナルで `ffmpeg -version` と `ffprobe -version` が動くことを確認します。
   - macOS: Homebrew で `brew install ffmpeg`
   - Ubuntu / Debian: `sudo apt update && sudo apt install ffmpeg fonts-noto-cjk`
   - Windows: `winget install Gyan.FFmpeg` の後、ターミナルを開き直します。
3. 無料の「Noto Sans CJK JP」フォントをインストールしてください。既存の日本語フォントを使う場合は画面の「字幕フォント」にそのフォント名を指定できます（Windows の例: `Yu Gothic`、macOS の例: `Hiragino Sans`）。
4. このリポジトリのフォルダーで実行します。

```bash
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell の場合は次のコマンド
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

PowerShell で仮想環境の有効化が拒否される場合は、代わりに `.venv\Scripts\python.exe -m pip install -r requirements.txt` と `.venv\Scripts\python.exe -m streamlit run app.py` のように直接実行できます。

## 画面での使い方

```bash
python -m streamlit run app.py
```

ターミナルに表示されたローカル URL を PC のブラウザで開きます。

1. 音声のある動画を1本選びます。
2. 必要なら BGM を選び、利用条件を確認したチェックを入れます。
3. 「動画を作成」を押し、処理の終了を待ちます。
4. 完成動画を再生して確認し、「完成動画を保存」でダウンロードします。

画面版は動画60秒・50MB、BGM50MB以下です。完成動画はセッション内のメモリだけに保持し、ダウンロードして保存します。ディスク上の入力・中間・完成ファイルは処理終了時（失敗時も）削除します。大きな素材はPCで下記CLIを使ってください。CLIの出力は指定した保存先に残ります。

## コマンドでの使い方

```bash
python -m reels input.mov outputs/reel.mp4
python -m reels input.mov outputs/reel-bgm.mp4 --bgm music.wav --bgm-rights-confirmed
# ダウンロード不要で映像編集だけ確認する
python -m reels input.mov outputs/reel-test.mp4 --no-subtitles
# 精度を上げる（処理時間・メモリ使用量は増えます）
python -m reels input.mov outputs/reel-small.mp4 --model small
```

出力先には未使用の `.mp4` ファイル名を指定してください。

## 編集内容と制限

- 初期設定で -35dB 以下が 0.7 秒以上続いた箇所をカットし、発話の前後に 0.15 秒残します。背景雑音が多い素材ではカットされにくく、小さな声は誤ってカットされることがあります。画面のしきい値をより低くすると小さな声を残しやすくなります。
- カット済み音声を日本語で認識し、白い太字・暗い縁取り・影の字幕を焼き込みます。字幕は18文字ごとに折り返し、画面下部の操作ボタンを避ける位置に配置します。誤認識はあり得ます。字幕の手動修正画面は未実装です。
- BGM は動画の長さまでループします。話し声を音量調整し、発話に応じて BGM を自動で下げます。
- 1080×1920、30fps、H.264 / AAC、MP4 で出力します。横長素材は中央を切り抜くため、端の人物や文字が切れる場合があります。人物追跡・複数素材の編集・Instagram への自動投稿は未実装です。
- 音声トラックのない素材はエラーになります。編集は同期処理で、途中キャンセルは未実装です。長い動画は処理時間・一時ディスク容量が増えます。
- モデル取得に失敗する環境では、Hugging Face の接続設定を確認してください。字幕オフでもその他の機能は使えます。日本語字幕が四角になる場合は日本語フォントをインストールし、フォント名を確認してください。

## BGM の著作権

音源を自動で取得・同梱しません。自分で制作した音源、または Instagram 投稿・商用利用・動画への組み込みが許可された音源を指定してください。「無料」「ロイヤリティフリー」だけでは利用許可の保証になりません。必要なクレジット表記、地域・期間・商用利用の条件を確認し、許諾の記録を保管してください。確認チェックは利用者による申告であり、アプリがライセンスを判定するものではありません。Instagram 内の楽曲も、外部で MP4 に組み込む権利があるとは限りません。BGM を指定しなければ、素材の音声のみで出力します（素材自身の権利も確認してください）。

## テスト

```bash
python -m unittest discover -s tests -v
```

無音区間・字幕エスケープの単体テストと、合成素材を実際の FFmpeg で処理し、1080×1920・H.264/AAC・無音カット・MP4 の全体デコードを検証する結合テストがあります。結合テストの音声認識は固定の日本語結果に置き換えるため、モデルをダウンロードせず字幕合成を検証できます。実モデルの認識精度は、このテストでは保証しません。

## このクラウド環境での検証結果

FFmpeg による字幕・BGM付き動画の生成、出力の全体デコード、無音区間・字幕の単体テスト、画面初期表示を検証しています。当初はモデル取得が403で失敗しましたが、環境公開後は tiny モデルの取得・読み込みが成功しました。そのため、実音声の日本語文字起こしはこの環境では未検証です。環境設定で Hugging Face とモデル配布先への接続を許可した後、音声のある動画で字幕付き出力を確認してください。API キーは不要です。

## Streamlit Community Cloud で使う

PC への Python インストールなしで利用するための配置手順です。クラウドでは素材をサーバーへアップロードして処理します。出力ファイルは処理終了時に削除し、メモリ内の完成動画をダウンロードできます。必要な動画は必ずダウンロードしてください。機密性の高い素材はアクセス範囲を確認してから利用してください。

1. このリポジトリのアプリファイルを GitHub の `main` に反映します。
2. https://share.streamlit.io/ で GitHub アカウントを使ってログインします。
3. アプリ作成の画面（Create app / New app）で、GitHub のリポジトリから配置する方法を選びます。
4. Repository: `yukina96/my-reels-editor`、Branch: `main`、Main file path: `app.py` を指定します。
5. Advanced settings で Python 3.12 を選択します。API キーや Secrets の入力は不要です。
6. Deploy を押します。`requirements.txt` の Python 依存関係と `packages.txt` の FFmpeg・日本語フォントがインストールされます。
7. 表示されたアプリの URL を開き、まず 10〜30 秒の短い音声付き動画で試します。字幕モデルは最初は `tiny` を選ぶと負荷を抑えられます。
8. 動画と、利用条件を確認した BGM を選び、「動画を作成」→完成動画を確認→「完成動画を保存」の順に操作します。

無料枠はメモリ・CPU・保存領域などに制限があり、長い動画や大きなモデルは失敗する可能性があります。クラウドでの配置と実音声認識はまだ検証していません。失敗時はアプリ管理画面のログを確認します。Codex の通信設定は Streamlit の環境には引き継がれません。有料プランや外部 API の契約はこの手順では不要です。

自分の PC だけで起動する場合は、`python -m streamlit run app.py --server.address 127.0.0.1` と指定できます。

## 素材の分離・削除とプライバシー

画面版は利用者のStreamlitセッション内だけに完成動画のバイト列を保持し、共有キャッシュ・共有出力フォルダーには保存しません。入力は各処理専用の一時ディレクトリ（Linuxでは0700）に保存し、正常終了・例外終了時に削除します。処理後はアップロード欄もリセットします。Streamlitの共有メディアURLを作らず、このセッションの埋め込み画面に直接渡したデータからダウンロードします。プレビューは削除し、保存後にPCで再生して確認します。

完成動画の表示期限は15分です。接続中は60秒ごとに期限を確認してメモリから削除します。「素材と完成動画を消去」でも削除できます。切断したセッションのメモリ解放はStreamlitのセッション終了処理に依存し、切断直後の削除は保証しません。プロセスの強制終了では一時ファイルの削除処理が走らない可能性があります。運営者・クラウド事業者からのアクセスや、ブラウザに届いたデータの保存・転送を防ぐ仕組みではありません。

顔を含む動画の利用前にStreamlit側の閲覧権限を確認してください。この変更は公開・非公開設定を変更せず、ログイン機能も追加しません。ログには動画内容・字幕・FFmpegの詳細エラーを出しません。無料環境向けに処理は同時に1件、CPU2スレッド、モデルtiny、素材60秒・50MBに制限しますが、無料枠での動作は実配置で確認が必要です。

`.gitignore`で素材・出力の主要形式、字幕、`.env`、Streamlit secretsを除外します。すでに追跡されたファイルや強制追加は防げません。公開前の検査では全ローカルGit履歴と作業ファイルに対する代表的なキー・秘密鍵・パスワード・メールのパターンを調べ、検出なし、過去の動画・音声ファイルもなしでした。ただしGitコミットの作者・記録者情報にはメールアドレス2種類があります。履歴は書き換えていません。一般的なパターン検査は個人情報の不存在を保証しません。
